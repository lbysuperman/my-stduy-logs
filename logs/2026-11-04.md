## 考前速记

### 一、今日核心知识（最重要）

- 调用处把实参交给参数，`return` 把值交回调用处，`print` 把内容显示到终端。字典 `data[key]` 按键取值，列表 `items[index]` 按从 `0` 开始的位置取元素。
- 字段是否存在看 `key in data`。有键但值为 `""` 时，取到的仍是空字符串。HTTP 响应体也可能确实为空，可记录成 `""`。
- HTTP 请求的方法、路径、请求体各有用途。GET 常用于读取资源，POST 常用于提交数据。HTTPS 提供传输加密。HTTP 状态码来自响应，连接超时可表现为客户端异常。
- `response.text` 取整个响应体的文本，`response.json()` 把 JSON 响应体解析成 Python 数据。对 httpbin 的这条回显，用外层 `json` 再取内层 `text`。
- `json.loads` 将 JSON 文本解析成 Python 数据，`json.dumps` 将数据转回 JSON 文本。以 `"a"` 模式写 JSONL，每条记录末尾加换行，旧记录保留。

### 二、我的薄弱点与易错点

- 方法选择和加密是两件事。说「用 POST 是因为要提交数据」，再单独说明「用 HTTPS 保护传输」。描述请求体时指出整个 JSON，而后才谈里面的键和值。两处已讲解，独立表达待验证。
- 「收到了 503 响应」和「业务请求成功」表达的是不同事实。这个脚本按有无请求异常分支，已用 503 变式答对。查看落盘记录时，`""` 表示拿到的内容为空，`null` 是本例中缺少响应数据时的占位。

### 三、最值得记住的解题方法

- 读代码时沿着数据走。先圈出输入从哪来，记下中间变量各是什么类型，再逐层取键，最后看哪条语句负责返回、显示或落盘。
- 排查请求时先确认程序走到了哪一步。读用例就失败，查路径和文件名。拿到响应，查状态码和响应体。连接超时且没拿到响应，查异常详情。需要复现或比较时，把输入和结果按 ID 成对保存。
